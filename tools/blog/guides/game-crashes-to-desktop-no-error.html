You're mid-match, the screen flicks, and you're looking at your desktop. There's no message and no report. The game is just gone. A game that crashes to desktop with no error feels like it left nothing behind, but Windows almost always wrote down what happened. Here's where to find it and what to do with it.

Find the error Windows did log

When a program hits a fault it can't handle, Windows ends it and logs an Application Error. The game often has no time to show its own message.

  1. Right-click Start and open Event Viewer.
  2. Go to Windows Logs > Application.
  3. Click Filter Current Log, type 1000,1002 in the event IDs box and click OK.
  4. Find the entry at the time of the crash, with your game's .exe as the faulting application.

Event 1000 is a crash. Event 1002 is a freeze that ended with the game being closed. In a 1000, three lines matter.

  • Faulting application name is the game's .exe and its version.
  • Faulting module name is the file the crash happened in. This is your best lead.
  • Exception code says what kind of fault it was.

Reliability Monitor shows the same thing as a calendar. Type reliability into Start, open View reliability history, and look for "Stopped working" under the game's name. A .NET game may also leave a .NET Runtime 1026 entry with the error's name, just before the 1000.

If there's no 1000 at all and the whole PC restarted, it wasn't a game crash. See PC restarts randomly while gaming instead.

What the faulting module tells you

  • If it's the game's own .exe, UnityPlayer.dll, GameAssembly.dll or an Unreal Engine file, the crash was inside the game. Update it, verify its files and remove mods.
  • nvwgf2umx.dll, nvd3dumx.dll and nvlddmkm.sys belong to the NVIDIA driver. amdxx64.dll and atiumd64.dll belong to the AMD driver. Files starting with igd belong to the Intel graphics driver.
  • d3d11.dll, d3d12.dll, dxgi.dll and vulkan-1.dll are the graphics layer. The fault is usually the driver's or the game's, not DirectX itself.
  • gameoverlayrenderer64.dll is the Steam overlay and DiscordHook64.dll is Discord's. RTSSHooks64.dll is RivaTuner Statistics Server, which MSI Afterburner uses for its overlay. nvspcap64.dll is the NVIDIA overlay.
  • KERNELBASE.dll and ntdll.dll are parts of Windows every program uses. The fault is most often still the game's, so treat it like the first case.
  • If it says unknown, Windows couldn't tell. Use the exception code instead.

These are the common exception codes.

  • 0xc0000005 is an access violation. The game touched memory it wasn't allowed to. Bugs, mods, overlays and unstable memory all cause it.
  • 0xc0000409 is a stack buffer overrun. The game found that part of its memory had been overwritten, or stopped itself on purpose after a serious error.
  • 0xc0000374 is heap corruption. Memory got damaged, often by a mod, an overlay or a bug.
  • 0xc000001d is an illegal instruction. The CPU hit an invalid instruction, which can point to an unstable overclock or undervolt.

Fixes, in the order worth trying

  1. Verify the game's files. In Steam, right-click the game in your Library and choose Properties > Installed Files > Verify integrity of game files. Epic, EA, Ubisoft and Battle.net have a Verify or Repair option in each game's menu. If it crashes within seconds of starting, also repair its anti-cheat if it has one. Easy Anti-Cheat, for example, has a Repair Service button in the setup file inside the game's folder.
  2. Turn off overlays one at a time. That means Steam, Discord, the NVIDIA app or AMD Software, and RivaTuner. If the faulting module is one of their files, start with that one.
  3. Remove mods, reshade files and injected tools, then test the plain game.
  4. Update or clean-reinstall the graphics driver if the faulting module belongs to it. If the crashes began after a new driver, try the one before.
  5. Undo tuning. Reset GPU overclocks, and in the BIOS turn off XMP or EXPO for a test. A memory profile that's slightly unstable is a classic cause of random crashes across several games.
  6. Test memory. Open Start, type Windows Memory Diagnostic, and pick Restart now and check for problems. The result appears in the System log under the source MemoryDiagnostics-Results.
  7. Check temperatures and memory use while playing. A GPU near its limit or RAM nearly full can both end a game. Windows logs event 2004, Resource-Exhaustion-Detector, in the System log when it's running out of memory.
  8. Repair Windows files. Open Terminal (Admin) and run sfc /scannow. If it finds problems it can't fix, run DISM /Online /Cleanup-Image /RestoreHealth and then sfc /scannow again.

A good test for any fix is the pattern. If the game crashes at the same place in the same file every time, it's the game or a mod. If it crashes in different files at random moments, it's the PC, so look at memory, tuning, heat and power.

How RigSight saves the digging

RigSight is a free, open-source monitor for Windows. Its Crashes page reads the same Application Error entries and turns the faulting module into plain words. It says "crashed inside the NVIDIA driver" instead of nvwgf2umx.dll, with what to try next. Every crash carries one word for how sure the cause is. It's Confirmed when Windows names a known file, Likely when the evidence points one way, Possibly when other causes fit too, and Not enough to say when it can't tell.

It also catches the patterns for you. A crash within a minute of starting reads "crashed as it was starting" and points at the game's files and anti-cheat. Three crashes at the same place in the same file read "crashes at the same spot every time", which is a fault in the game, not your hardware. RigSight puts a crash down to the install when a graphics driver was being installed at the time.

Opening a crash shows the 45 minutes before it. You see temperatures, load, power, memory, fans and network, and which app was using the CPU and GPU. For a game, RigSight also keeps the last five minutes before the crash at a reading every 2 to 3 seconds. What it wasn't lists what it ruled out, like "It wasn't overheating" or "Memory wasn't full", and it says when graphics memory was nearly full and well above that game's usual. You also get a notification with the game's name the moment it happens, and the play on the Games page says it ended in a crash. CPU temperature needs RigSight running with admin rights.

Your next step is to find the Application Error 1000 for your last crash and read its faulting module. If it's the game's own file, verify the files first. If it's an overlay's file, turn that overlay off and play again.
