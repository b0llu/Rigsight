The screen goes black for a second, the game freezes or closes, and a note in the corner says "display driver stopped responding and has recovered". You may not see the note at all, only the flicker. Either way, Windows just reset your graphics driver. Here is what that means and how to stop it happening.

What "display driver stopped responding and has recovered" means

Windows has a safety net called Timeout Detection and Recovery, or TDR. When the graphics card takes on a task, Windows expects it done or paused within a time limit. Microsoft gives the default as two seconds. If the card misses it, Windows treats the card as frozen, resets the graphics driver, clears the graphics memory and redraws the desktop. That reset is the flicker you see.

Most of the time the desktop comes back fine. The game that was running often doesn't, because it lost its connection to the graphics card. Some games recover, some show a black screen, and many simply crash.

If resets pile up quickly, Windows stops trying. By default, once the card has hung and recovered five times within a minute, the next hang ends in a blue screen. A recovery that fails also ends in a blue screen, called VIDEO_TDR_FAILURE, stop code 0x116, often naming nvlddmkm.sys on NVIDIA cards or amdkmdag.sys on AMD cards.

Where Windows records the resets

Windows logs a reset in a few places, and the names are worth knowing, because forum answers use them all.

  • Event Viewer, Windows Logs > System: an entry from source Display with Event ID 4101, saying the display driver stopped responding and has recovered.
  • On NVIDIA cards, the System log also holds entries from source nvlddmkm. Event 153 usually reads as a TDR reset on the GPU. Event 13 is a graphics exception with an error code in its data.
  • Reliability Monitor: search Start for reliability and open View reliability history. A reset shows as Hardware error. Its details say LiveKernelEvent with code 141 or 117. 141 means one graphics engine stopped answering, 117 means the whole card did, and in both cases Windows recovered it.

Write down the times. Whether the resets happen in one game or in everything, at idle or only under load, tells you more than the error itself.

Fix it, in this order

1. Update, roll back or clean install the graphics driver

The driver is the most common cause and the easiest to test. If the resets started right after a driver update, roll it back: Device Manager > Display adapters > right-click your card > Properties > Driver > Roll Back Driver. If you have been on the same driver for months, update it. Either way, use the clean install option: on NVIDIA, pick Custom (Advanced) and tick Perform a clean installation. On AMD, use the installer's Factory Reset option, which removes earlier versions of AMD Software and means you can't roll back to them afterwards. The full steps, and when DDU is worth it, are in games crashing after a graphics driver update.

2. Put the graphics card back to stock clocks

An overclock or undervolt that is almost stable is a classic cause of TDRs. The card makes a mistake under a certain load, stalls, and Windows resets it. Reset MSI Afterburner or your card maker's tool to default and turn off any automatic tuning. Some cards ship with a factory overclock, and some have a switch for a quiet BIOS that runs lower clocks. Try it if yours has one.

3. Check the GPU's temperature

A card that overheats slows itself down, and if that isn't enough it can hang. Watch the GPU temperature and the hot spot temperature while you play, using a monitor that keeps a history. NVIDIA lists a maximum GPU temperature on the specification page for many of its cards, and it differs by model. The hot spot, which AMD calls junction temperature, normally runs well above the main GPU reading, so judge each against its own limit. If your card sits at its limit, clean the dust out, check the fans spin and give the case more airflow.

4. Check the power

When a graphics card's power use jumps, a tired or undersized power supply can dip for a moment and the card stalls. Make sure every power plug on the card is fully seated. If your card takes two or three power plugs, check the manuals for the card and the power supply. Some ask for a separate cable from the power supply to each plug instead of one cable with two plugs on it, and with a card that draws a lot of power that is the safer choice where your supply has enough cables. If resets only come at the heaviest moments of a game, the power supply is a real suspect.

5. If it is always the same game

Resets in one game while others run fine point at that game. Update it, verify its files in the launcher, turn off its overlays, and try a lower graphics preset or a different graphics mode such as DirectX 11 instead of DirectX 12, if the game offers one.

6. Leave TdrDelay alone

Many old guides tell you to raise TdrDelay in the registry so Windows waits longer. Microsoft documents those registry keys only for testing and debugging during driver development, and says end users shouldn't change them. A longer wait can hide the message, but the card still hangs, and now the PC sits frozen for longer before anything happens. Wrong registry edits can stop Windows working, so leave it alone and fix the cause instead.

7. When nothing helps

If resets carry on with a clean driver, stock clocks, normal temperatures and a solid power supply, the card itself may be failing. Testing it in another PC, or another card in yours, settles it. If it is under warranty, the error codes and times you wrote down are exactly what the maker will ask for.

How RigSight tracks graphics driver resets

Resets are easy to miss. The game closes, the desktop comes back, and a week later you can't say how often it happened. RigSight is a free, open source PC monitor that records them as they happen and keeps them.

The Crashes page counts graphics driver resets in a tile of their own, read from the same Windows records described above: the Display event and the LiveKernelEvent hang reports. Each one opens with what RigSight recorded in the minutes around it, such as GPU temperature, hot spot, power and load, so you can see whether the card was hot or pulling hard at that moment. When there are several, "What they have in common" says whether they all happened in one game or across different apps, which is the same question as step 5 above.

Start with a clean install of the driver and stock clocks, then play as you normally do. If the resets stop, you are done. If they come back, check the temperature and power at the moment they happen. A one-off reset after hours of play is rarely worth worrying about. Several a day is something to fix.
