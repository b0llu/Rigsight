Your games ran fine last week. You installed a new graphics driver, and now a game drops to the desktop or freezes halfway through a match. Games crashing after a graphics driver update is common, and it is one of the easier crashes to test, because you can put the old driver back in a couple of minutes. If the crashes stop, you have your answer.

Check that the driver really is the change

Before you undo anything, make sure the timing lines up. A game patch, a Windows update or a new overlay the same week can look exactly like a driver problem.

  1. Open Settings > Windows Update > Update history and look under Driver updates. Windows sometimes installs a graphics driver on its own, so this catches updates you never ran yourself.
  2. Open Device Manager, expand Display adapters, right-click your graphics card and pick Properties. The Driver tab shows the driver version and date.
  3. Check your game launcher for an update to the game on the same day.

Then look at how the game crashed. Open Event Viewer > Windows Logs > Application and find the Error from Application Error at the time of the crash. The line Faulting module name says which file it crashed in. Files like nvwgf2umx.dll or nvd3dumx.dll belong to the NVIDIA driver, and files starting with amdxx or atiumd belong to AMD's. A crash inside one of those points at the driver. A crash inside the game's own files points at the game. For more on reading these logs, see how to find out why your PC crashed.

Roll the driver back in Device Manager

This is the quickest test, and it is safe. Windows keeps the previous driver when a new one goes in, and these are Microsoft's own steps for putting it back. You need to be signed in as an administrator.

  1. Open Device Manager and expand Display adapters.
  2. Right-click your graphics card and pick Properties.
  3. Open the Driver tab and press Roll Back Driver.
  4. Pick a reason, press Yes, and restart if Windows asks.

If Roll Back Driver is greyed out, Windows didn't keep an older version. Download the driver you had before from NVIDIA's driver page or AMD's support page, where older versions are listed for each card, and install it with the clean install option described below.

Play the games that crashed for a few sessions. If they now run fine, the new driver was the problem. Stay on the old one until a newer driver lists your game as fixed. NVIDIA's release notes have a section of open issues for each driver, and it is worth a look before you update again.

If Windows Update keeps putting the newer driver back, Microsoft's Show or hide updates troubleshooter, a small file called wushowhide.diagcab, can hide that one driver update. Microsoft made it for Windows 10, and guides report it still works on Windows 11. A newer version of the same update can still install later.

Do a clean install of the driver

Sometimes the new driver is fine and the install is the problem. Settings and profiles left from older versions can clash with the new one. A clean install removes them and puts the driver in fresh.

For NVIDIA:

  1. Download the driver for your card from NVIDIA's driver page.
  2. Run the installer and accept the license.
  3. On the installation options screen, pick Custom (Advanced).
  4. Tick Perform a clean installation and continue. The exact screens can differ a little between driver versions.
  5. Restart when it finishes.

Your screens can flicker or go black for a moment during the install. That is normal. A clean install also resets your NVIDIA Control Panel settings, so note any per-game settings you care about first.

For AMD, AMD's advice is to remove AMD Software first from Settings > Apps > Installed apps, then install the new version from AMD's support page. If a normal uninstall leaves things broken, AMD offers the AMD Cleanup Utility for problems an uninstall can't fix. The AMD installer also has a Factory Reset option that removes all earlier versions of AMD Software as part of the install. AMD notes that you can't roll back to the old driver after that.

Use DDU only when a clean install isn't enough

Display Driver Uninstaller, usually called DDU, removes every trace of a graphics driver. It is a well known free tool, but its own developer says it was designed for cases where the normal driver uninstall fails, and its guide also covers switching between NVIDIA and AMD cards. It isn't something to run on every update.

If you do use it, follow the developer's guide:

  1. Download the driver you want to install first, so it is ready offline.
  2. Back up anything important, and have your BitLocker recovery key to hand if the drive uses BitLocker.
  3. Disconnect from the internet, so Windows Update can't slip its own driver in.
  4. Restart into Safe Mode and run DDU there. The developer strongly recommends Safe Mode.
  5. Restart, install the driver you downloaded, then reconnect.

Things a new driver can bring to the surface

If the crashes carry on after a rollback and a clean install, the driver probably isn't the whole story. A new driver can push something that was already borderline over the edge.

  • Overclocks and undervolts: a setting that was stable on the old driver can fail on the new one. Reset MSI Afterburner or your card maker's tool to default and test at stock clocks.
  • Overlays: the Steam, Discord, NVIDIA and RivaTuner overlays all hook into the game. Turn them off one at a time to see whether one of them is crashing it.
  • Game files: use your launcher's verify or repair option. After a driver change, the first launch can also take longer while the game rebuilds its shader cache. That is a slow start, not a crash.
  • Heat and power: if the crash comes after a long stretch under load, check GPU temperatures and look at your power supply. A driver that lets the card boost higher can show up a weak one.

If every game crashes and the screen goes black before Windows recovers, you are probably seeing graphics driver resets rather than ordinary game crashes. That has its own guide: display driver stopped responding and has recovered.

How RigSight shows what the driver did

The hard part of this problem is remembering what changed and when. RigSight, a free and open source PC monitor, keeps that record for you from the day you install it.

The Timeline lists every driver install with its time, and for the graphics driver it shows the new version and the one it replaced. The "This PC now" panel shows the graphics driver you are on and since when. When a driver made your PC better or worse, the Timeline says so under it, and the Before and after filter lists only those changes. Opening one shows the same game at the same load before and since, with the warmth of the room taken out, and the problems a graphics driver can cause, such as graphics driver resets. A driver that made no difference it could measure gets no line at all.

The Crashes page names a crash that happened inside an NVIDIA, AMD or Intel driver file. When a game crashed or froze within two minutes of a graphics driver being installed, it says the driver was being installed at that moment, because open apps can crash while a driver is swapped under them. That crash says nothing about whether the new driver is any good. An opened crash also lists the drivers and Windows updates from the seven days before it.

On the Games page, each game lists every play and how it ended, with the driver updates that came between plays. Frame rates there need RivaTuner Statistics Server running. With that history, "it started after the update" is something you can look up instead of something you have to remember.

Start with the rollback. It takes five minutes and tells you more than any amount of searching forum threads. If the old driver crashes too, look at the game, your clocks and your temperatures, and if the game just closes with no message at all, read why a game crashes to desktop with no error.
